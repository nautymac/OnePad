# OnePad — abxylute 3D One 터치패드 / 백버튼 / 자이로 변환 서비스

Steam 컨트롤러가 동작하는 방식 그대로, 컨트롤러의 벤더 HID 채널을 직접 읽어
터치패드·백버튼(그립)·자이로를 마우스/스크롤/키 입력으로 바꾸는 **사용자 모드 전용 서비스**입니다.
가상 게임패드 에뮬레이션(ViGEm 등)과 커널 드라이버는 쓰지 않습니다.
C++ 네이티브(LLVM-MinGW clang)로 빌드되며 런타임 의존성은 벤더 DLL(`sapjoyapis.dll`) 하나뿐입니다.

## 폴더

| 경로 | 내용 |
|---|---|
| `bin\onepad.exe` | 서비스 본체 (트레이 상주, 관리자 권한 필요) |
| `bin\probe.exe` | 실험용 CLI (펌웨어 설정 조회/변경, 벤더 리포트 덤프) |
| `bin\sapjoyapis.dll` | 벤더 SDK (Gear\Settings 에서 복사) |
| `src\` | 소스 (`main.cpp`, `engine.h`, `vendor.h`, `devctl.h`, `config.h`, `output.h`, `common.h`) |
| `tools\probe.cpp` | probe 소스 |
| `build.ps1` | 빌드 |
| `Install-OnePad.ps1` | 로그온 시 자동 시작(최고 권한) 작업 등록 + 즉시 시작 |
| `Uninstall-OnePad.ps1` | 중지 + 펌웨어/장치 원복 + 작업 삭제 |
| `%LOCALAPPDATA%\OnePad\onepad.ini` | 설정 (첫 실행 시 기본값으로 생성) |
| `%LOCALAPPDATA%\OnePad\onepad.log` | 로그 |
| `%LOCALAPPDATA%\OnePad\firmware-backup.ini` | 서비스가 바꾸기 전의 펌웨어 원본 설정 |

## 동작 원리

- **입력**: `sapjoyapis.dll` 의 상태 콜백(초당 125회)으로 59바이트 벤더 리포트를 받습니다.
  양쪽 패드 절대 좌표(0~1024), 백버튼 비트(왼쪽 0x10, 오른쪽 0x80), 좌/우 IMU(가속도+자이로)가 들어 있습니다.
- **패드 모드** (패드별, 트레이 메뉴 또는 ini):
  - `mouse` 트랙볼 마우스(관성 감쇠, 탭=클릭) · `scroll` 휠 스크롤 · `dpad` 4/8방향 키
  - `native_touchpad` / `native_wheel` / `native_leftstick` / `native_rightstick`: **펌웨어가 직접** 포인터/휠/스틱으로 변환 (서비스는 손대지 않음)
  - `off`
- **모드 시프트**: 그립을 누르는 동안 `shift_mode` 로 전환 (기본: 왼쪽 그립 = 모드시프트, 오른쪽 패드 마우스→스크롤, 왼쪽 패드 스크롤→D패드)
- **그립 액션**: `modeshift`, `gyro_hold`, `gyro_toggle`, `key:CTRL+C`, `mouse:left|right|middle|x1|x2`, `none`
- **자이로 → 마우스**: 활성 조건 `always | grip | right_touch | toggle`, 중력 기준 수평 회전(yaw=world) + pitch 축 선택, 감도/반전
- **패드 진동(햅틱)**: 펌웨어 터치패드 모드(1)에서만 진동이 납니다. `haptics=1` 이면 그 모드로, `0` 이면 휠 모드(4)로 두고 둘 다 서비스가 좌표를 읽습니다.
- **Windows 쪽 커서/휠 누수 차단**: 서비스가 동작하는 동안 컨트롤러의 HID 컬렉션 노드
  (정밀 터치패드 COL03/COL05, 마우스 COL02)를 비활성화하고, 종료 시 다시 활성화합니다. 그래서 관리자 권한이 필요합니다.
- **백버튼**: 실행 중 펌웨어 키매핑을 M1→M1, M2→M2(기능 없음)로 바꿔 L3/R3 입력이 섞이지 않게 하고 종료 시 원복합니다.

## Steam Deck 컨트롤러 에뮬레이션 (`[deck]`)

OnePad 자체가 USB/IP 장치 서버(127.0.0.1:3240)를 열고 **Steam Deck 컨트롤러(28DE:1205)** 의 USB 신원
(디바이스/구성 디스크립터 5개 인터페이스, 문자열, HID 리포트 디스크립터)을 그대로 내보냅니다. 가상 USB 전송에는
서명된 범용 드라이버 **usbip-win2**(vadimgrn, WHLK 서명)만 필요하고, 장치 에뮬레이션 자체는 전부 OnePad 코드입니다.

- 입력: 64바이트 Neptune 프레임(`01 00 09 40` 헤더, 4 ms 주기)에 XInput 버튼/스틱/트리거, 양쪽 패드 좌표+터치 비트,
  IMU(가속도 16384/g, 자이로 16.384/dps), 백버튼 → **L4/R4**(L5/R5는 항상 떼짐).
- Steam 핸드셰이크: `0x83` 속성, `0xAE` 시리얼(보드/유닛), `0x87` 설정 에코, `0x81` 매핑 해제 → **점유**, `0x85/0x8E` → 해제, `0xEB` 진동 → 실제 패드 진동(XInput).
- **Steam 없이도 동작**: Steam이 점유(리저드 모드 off)하기 전까지는 위 변환 엔진이 그대로 돌고, 점유하면 변환을 멈추고 Deck 프레임만 보냅니다. Steam이 놓으면 다시 변환합니다.
- 자체 테스트: `bin\usbip-selftest.exe` 가 USB/IP 클라이언트 역할로 디스크립터·feature 채널·4 ms 페이싱·UNLINK를 검사합니다 (PASS 확인됨).

설정 `[deck] enabled=1`, `auto_attach=1` 이면 시작 시 `usbip.exe attach -r 127.0.0.1 -b 1-1`, 종료 시 `detach --all` 을 실행합니다.

## 실행 / 설치

```powershell
# 수동 실행 (관리자 PowerShell)
C:\Users\nauty\OnePad\bin\onepad.exe            # 트레이 아이콘
C:\Users\nauty\OnePad\bin\onepad.exe --console  # 콘솔에 로그 출력 (debug=1 이면 상태도 출력)
C:\Users\nauty\OnePad\bin\onepad.exe --stop     # 실행 중인 서비스 정상 종료
C:\Users\nauty\OnePad\bin\onepad.exe --restore  # 펌웨어/장치 노드만 원복하고 종료
C:\Users\nauty\OnePad\bin\onepad.exe --config   # 설정 파일 열기

# 로그온 자동 시작 등록
powershell -ExecutionPolicy Bypass -File C:\Users\nauty\OnePad\Install-OnePad.ps1
# 제거
powershell -ExecutionPolicy Bypass -File C:\Users\nauty\OnePad\Uninstall-OnePad.ps1
```

## 기본 설정 요약 (`onepad.ini`)

- 오른쪽 패드: `mouse` (시프트: `scroll`), 진동 꺼짐
- 왼쪽 패드: `scroll` (시프트: `dpad` 화살표), 진동 꺼짐
- 왼쪽 그립: `modeshift`, 오른쪽 그립: `gyro_hold`
- 자이로: `mouse`, `activate=grip` (오른쪽 그립을 누르는 동안 자이로 조준), IMU=오른쪽 반쪽

## probe.exe

```
probe info                 버전 / 패드 모드 / 패드 on-off / 백버튼 매핑 표시
probe tpmode L|R 1..4      1=터치패드(포인터, 진동) 2=왼스틱 3=오른스틱 4=휠
probe tpstatus L|R on|off
probe keymap L|R 28 28     M1(28)/M2(32) 매핑 (3=L3, 8=R3)
probe dump 20              벤더 리포트 20초 덤프 (패드 좌표, 버튼 바이트, XInput 변화)
```

## 알아낸 하드웨어 사실

- USB 복합 장치 VID 2993 / PID 0012: MI_00 XInput(XUSB), MI_01 키보드+마우스+정밀터치패드×2, MI_02 벤더(FFA0).
- 벤더 리포트(rid 4, 64B) = 헤더 5B + `SAPJOY_GAMEPADSTATE_2`(59B): 배터리/상태 9B, 스틱 4B, 버튼 4B
  (buttons2: A 0x80 B 0x40 LB 0x08 LT 0x04 RB 0x02 RT 0x01 / buttons1: Setup 0x80 Home 0x40 ↑0x08 ↓0x04 ←0x02 →0x01 / buttons3: 그립),
  트리거 2B, testMode, 휠(0x80=정지), 오른쪽 패드 XY(BE), 좌/우 패드 상대 dx dy(터치패드 모드에서만),
  좌 IMU(ts + accel xyz + gyro xyz, int16 BE), 우 IMU, 왼쪽 패드 XY(BE).
- 가속도 1g ≈ 4096 LSB. 자이로 스케일은 미확인(기본 16.4 LSB/dps 가정, `scale_dps` 로 조정).
- 패드 클릭(물리 버튼)은 어느 리포트에도 없음 → 탭으로 대체.

## 실제 Xbox 패드 숨김 (`[hidhide]`) — 기본 auto

Steam은 3D One의 Xbox 360 인터페이스와 Deck 에뮬 장치를 둘 다 보고(Steam의 "Xbox 컨트롤러 Steam 입력" 설정은 무시됨), XInput 게임도 원래 패드를 직접 읽으므로
같은 버튼이 1P(Deck)와 2P(Xbox)로 두 번 들어간다. HidHide(Nefarius, 서명 드라이버)를 설치하면 OnePad가 자신을 화이트리스트에 넣고
`USBVID_2993&PID_0012&MI_00`(XUSB) 과 `HIDVID_2993&PID_0012&IG_00`(DirectInput) 두 노드를 숨긴다. 사용자 결정(2026-11-06): "스팀덱 컨트롤러만 있으면 된다".
- `mode=always`(2026-11-07부터 실제 사용값): 컨트롤러가 꽂혀 있는 한 항상 숨김, OnePad 종료 후에도 유지 — Steam이 언제 (재)시작하든 실제 패드를 볼 수 없다. 비Steam XInput 게임은 Steam 라이브러리에 추가해 실행.
- `mode=auto`: Steam 실행 중 + Deck 에뮬 연결 중에 숨김. Steam이 사라져도 `grace_s`(기본 45초) 동안은 숨김을 유지하고, OnePad 시작 직후와 `--stop` 재시작 때도 숨김을 유지한다. 이유(2026-11-07 확인): Steam은 시작 1초 안에 실제 패드를 "XInput Controller #1"로 잡고 그 뒤 숨겨도 놓지 않으므로, Steam이 (재)시작하는 순간에 이미 숨겨져 있어야 한다. 유예가 지나면 복귀(비Steam XInput 게임은 원래 패드 사용).
- `mode=always` / `mode=never`.
- 2026-11-06에 HidHide를 지웠다가 되돌림: Azahar 멈춤은 HidHide 탓이 아니라 SDL 교착이었고(아래 문제 해결 메모), HidHide가 없으면 Steam이 원래 패드를 2P로 잡는다.
설치: 관리자 PowerShell에서 `winget install --id Nefarius.HidHide --exact` (설치 후 OnePad 재시작, 필터 드라이버는 재부팅 후 확실히 동작).

## 완전 자동 운용 (사용자 개입 없음)

- **첫 실행이 곧 설치**: `bin\onepad.exe` 를 한 번 실행하면 로그온 자동 시작 작업(`OnePad`, 최고 권한, 로그온 8초 뒤, 시간 제한 없음, 실패 시 1분 간격 3회 재시작)을 스스로 등록합니다. 트레이 → "로그온 시 자동 시작"으로 끄고 켤 수 있고, ini `[general] autostart` 와 연동됩니다.
- 모든 보조 프로세스(usbip.exe, HidHideCLI.exe, schtasks.exe)는 창 없이 실행됩니다. 사용자에게 보이는 것은 트레이 아이콘뿐입니다.
- **3D One 컨트롤러가 없으면 아무것도 하지 않습니다.** 가상 Steam Deck 장치는 3D One이 연결된 동안만 꽂히고(분리 시 자동 detach), HidHide 숨김도 풀립니다. 다른 컨트롤러를 쓰는 동안 Steam에 유령 Deck이 남지 않습니다.
- 제거: `onepad.exe --uninstall` (실행 중 인스턴스 종료 → 작업 삭제 → 펌웨어/노드/HidHide/usbip 원복) 또는 `Uninstall-OnePad.ps1`.

## 문제 해결 메모

- **Steam에 Deck 컨트롤러가 안 보임**: `usbip.exe port` 는 "device in use" 인데 장치 관리자에 28DE:1205 가 없으면 usbip 가상 호스트 컨트롤러(`ROOT\USB\0000`)가 분리/재연결 반복 후 멈춘 것입니다. OnePad는 attach 후 6초 안에 열거되지 않으면 자동으로 분리 → 호스트 컨트롤러 재시작 → 재연결합니다(로그 `deck: attached but not enumerated; restarting ...`). 수동: `usbip detach --all` → `pnputil /restart-device "ROOT\USB\0000"` → `usbip attach -r 127.0.0.1 -b 1-1 --once`.
- **패드 진동 토글이 반영 안 됨**: 펌웨어 쓰기가 간혹 -3 으로 실패합니다. OnePad가 읽어서 검증하고 재시도합니다(로그 `not confirmed, will retry`).
- **패드 방향 반전**: `[pad.left]`/`[pad.right]` 의 `flip_x`, `flip_y`.

### usbip 가상 호스트 컨트롤러 고착 예방 (2026-11-05)
- 시작: 서버를 열기 전에 `attach ... --stop`(자동 재연결 시도 취소) → `detach --all`(묵은 포트 제거) → 그 다음 새로 attach.
- 종료/분리: 서버가 살아 있는 동안 `detach --all` → `attach --stop` → 그 뒤에야 서버 소켓을 닫음.
- 디바운스: 3D One이 사라져도 `[deck] detach_delay_s`(기본 90초) 동안 가상 장치를 유지. 절전·재접속 때 뽑았다 꽂지 않음.
- 점검: attach 후 6초 내 미열거 시 호스트 컨트롤러 재시작 후 재연결, 이후 30초마다 열거 상태 확인.

### Steam에서 1번 컨트롤러가 되게 하는 구성 (2026-11-05 밤 확정)
- 3D One의 Xbox(XUSB) 노드는 Windows가 비활성화를 거부하고(`CR_NOT_DISABLEABLE`), 펌웨어 키보드/마우스 모드에서도 XInput 장치는 남으며, HidHide는 Steam 자체(WGI 경로)에는 통하지 않습니다.
- 그래서: **Steam 설정 → 컨트롤러 → Xbox 컨트롤러 지원 끄기**(`localconfig.vdf`의 `SteamController_XBoxSupport=0`) + HidHide `mode=auto`(게임 프로세스에서 Xbox 패드 가림) + Deck 에뮬. 이 상태에서 Steam은 Deck 에뮬에 XInput 슬롯 0을 줍니다.
- 증상 "A→오버레이, X/Y→Steam 키보드"는 Deck 에뮬이 2번 컨트롤러로 밀려 데스크톱 레이아웃이 유지될 때 나타납니다. Steam 재시작 후 슬롯 0을 받으면 사라집니다.
- Deck 프레임은 이제 XInput 없이 벤더 리포트로만 만듭니다(버튼 비트: A 0x80 B 0x40 X 0x20 Y 0x10 LB 0x08 RB 0x02 (buttons2), L3 0x20 R3 0x10 십자 0x08/0x04/0x02/0x01 Home 0x40 Setup 0x80 (buttons1), View/Menu는 `[deck.buttons]`).

### 패드 라우팅 (2026-11-05 22:25)
- `[deck] pads_to_steam=games_only`(기본, 2026-11-07부터 라이브 설정도 이것): Steam이 장치를 점유해도 **Steam 게임 창 또는 Steam 창(컨트롤러 설정 메뉴 포함)이 앞에 있을 때만** 패드·그립·자이로를 Deck 프레임으로 보냅니다. 데스크톱(또는 Steam 창)에서는 OnePad 엔진이 패드를 처리하므로 탭=왼쪽 클릭, 탭 직후 다시 대고 끌기=드래그, 민감도 등 OnePad 설정이 그대로 적용됩니다. 버튼·스틱·트리거는 `buttons_to_steam=games_only`(기본)일 때 Steam 게임 또는 Steam 창이 앞에 있을 때만 Deck 프레임에 실리고, 그 밖(데스크톱, Azahar 같은 비Steam 앱)에서는 Steam·QAM 버튼만 남기고 비웁니다. 그래야 Steam 데스크톱 레이아웃이 B=Space, X=PageUp 같은 키 입력을 만들지 않고, 앱은 실제 3D One 패드(XInput)를 그대로 씁니다. `always`로 바꾸면 예전처럼 항상 전달. 백버튼(L4/R4)도 이 버튼 라우팅을 따른다(2026-11-07): Steam 게임에서는 Steam 설정이 정한 대로(예: L4=Tab), 데스크톱에서는 OnePad의 `[grip.*] action`(마우스 클릭).
- 게임 판별: 앞 창 프로세스에 Steam 오버레이 DLL(GameOverlayRenderer)이 로드돼 있으면 게임.
- `always` 로 두면 이전처럼 점유 중엔 전부 Steam에 맡깁니다.
- 패드 압력 `pad_pressure=0`: 터치가 Steam에서 "트랙패드 눌림"으로 해석되지 않게 함.

### SDL 기반 앱(Azahar 등)이 창 없이 멈출 때 (2026-11-06)

증상: Azahar를 닫고 몇 초 안에 다시 실행하면 프로세스만 있고 창이 안 뜸(CPU 거의 0). 원인은 HidHide가 아니라
Azahar에 내장된 SDL이 OnePad의 가상 Steam Deck(28DE:1205)을 자기 hidapi Steam Deck 드라이버로 여는 과정에서
SDL 조이스틱 락 ↔ Windows.Gaming.Input 콜백이 교착하는 SDL 쪽 버그. 재현 4회 중 2회, `SDL_JOYSTICK_HIDAPI_STEAMDECK=0`
환경변수로 실행하면 0회. 이 변수를 시스템 전역으로 두면 Steam도 Deck 페르소나를 무시하므로 **앱별로만** 적용한다.
- `tools/sdl-launch.cpp` → `azahar-launch.exe`(같은 폴더의 azahar.exe를 그 변수와 함께 실행). `D:\Azahar\azahar-launch.exe`에
  두고 시작 메뉴·바탕화면 바로가기를 여기로 돌렸다(아이콘은 azahar.exe 것). 다른 SDL 앱(Dolphin, PCSX2 등)도 같은 증상이면
  같은 방법(소스의 `azahar.exe`만 바꿔 빌드).
- 이때 Azahar는 Deck 페르소나 대신 실제 3D One Xbox 패드(XInput)를 컨트롤러로 쓴다.

### Azahar를 Steam 라이브러리에서 실행 (2026-11-06 결정)

비Steam 앱에서는 Steam이 가상 Deck에 데스크톱 레이아웃을 적용해 B=Space 같은 키가 들어오므로, Azahar는 **Steam에 비Steam 게임으로 등록**해서
Steam Input 게임 설정으로 쓴다(사용자 결정). 등록 항목: `D:\Azahar\azahar-launch.exe`(SDL 교착 우회 래퍼). Steam에서 실행하면 오버레이가 붙고
OnePad가 버튼·스틱·트리거를 Steam으로 넘기며, Steam은 Azahar용 설정(8월에 만든 것)을 Deck에 적용한다.
- `SteamController_XBoxSupport=0`은 Steam 시작 때만 적용된다. 실행 중에 실제 패드가 새로 보이게 되면 Steam이 그 패드를 Xbox 컨트롤러로 잡아
  데스크톱 레이아웃을 입히므로, 패드 가시성이 바뀐 뒤에는 Steam을 재시작한다(반드시 `explorer.exe "D:\Steam\steam.exe"`로, 관리자 셸에서 직접 띄우지 말 것).
- (2026-11-07) Steam 라이브러리에서 실행할 때도 같은 교착이 났는데(이번 방아쇠는 Steam 오버레이의 입력 훅), 래퍼에 `SDL_JOYSTICK_WGI=0`을 추가하니 해결됐다(Steam 경유 5/5, 직접 3/3).
  SDL은 XInput/DirectInput/RawInput 백엔드로 계속 패드를 본다. 8월 메모의 "오버레이 DLL이 원인"은 이 교착을 오버레이가 건드린 것이었다.
- (2026-11-07) Steam은 Deck 트랙패드 클릭을 **압력**으로 판단한다(클릭 비트만 보내면 무시, 압력 12000만 보내면 클릭 유지). 그래서 탭 펄스 동안 `[deck] tap_pressure`(기본 32767)를 함께 보낸다. Steam 설정에서는 트랙패드 "클릭"에 마우스 왼쪽 버튼을 넣고 "터치"는 비워 둔다.
